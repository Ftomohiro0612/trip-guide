## 5. 採用対象の定義

### Hub掲載の必須条件

次をすべて満たすイベントだけを `/events/summer` に掲載する。

1. 2026年6月〜9月の開催で、具体的な日付または開催期間を公式一次情報で確認できる
2. 東京・神奈川・千葉・埼玉のいずれかで開催される
3. 親子で参加・観覧できる
4. 次の4分類のいずれかに明確に該当する
5. 個別の公式URL、確認日、料金、予約要否、雨天・中止条件を可能な範囲で保持する
6. 年付きHub ID `summer-2026` を編集判断で `feature_hubs` に付与している

### 4分類

| `event_type` | 表示名 | 採用基準 |
|---|---|---|
| `fireworks` | 花火大会 | 実際の屋外打上花火が主目的または明確な主プログラム。映像・展示内の花火表現は除外 |
| `summer_festival` | 夏祭り・盆踊り | 夏祭り、地域祭り、盆踊り、屋外の縁日が主目的。単発の館内ミニ縁日は原則除外 |
| `summer_tradition` | 縁日・灯籠・風鈴 | 灯籠、風鈴、提灯、夕涼みなど、夏の伝統的な風景・回遊体験が主目的 |
| `night_outing` | 夜のおでかけ | 動物園・水族館・牧場・公園等の夜間開園や夜間営業。主役2分類とは別の補助枠 |

1イベントに表示上の主分類は1つだけ付ける。複数要素がある場合は「そのイベントを選ぶ主な理由」で決め、補足要素は既存 `tags` に残す。

### 掲載しないもの

- 夏休みというだけの展示、企画展、工作、学習講座、サマースクール
- 屋内演出として花火を扱うだけの展示・ショー
- 大人向け・飲酒中心で、親子利用を想定しない催し
- 2026年の開催日を一次情報で確定できないもの
- まとめサイトやSNS投稿しか根拠がないもの
- 中止、終了、公式情報の鮮度切れ

### 主役と補助枠の構成基準

- `fireworks` + `summer_festival` をハブ掲載全体の **70%以上** にする
- `night_outing` は **20%以下** を目安とし、Hero直下の主力枠には入れない
- 4都県それぞれで花火大会・夏祭りの両方を確保する
- 件数のために展示・ワークショップを混ぜない

## 6. 最小分類モデルと必要な互換対応

### 年付きHub IDと分類に追加する2項目

```ts
type SummerEventType =
  | "fireworks"
  | "summer_festival"
  | "summer_tradition"
  | "night_outing";

type FeatureHubId = "summer-2026";

event_type?: SummerEventType;
feature_hubs?: FeatureHubId[];
```

Hub抽出条件は、タグやタイトルの部分一致ではなく次に固定する。

```text
feature_hubs に "summer-2026" を含む
AND event_type が4分類のいずれか
AND 2026年夏の開催期間と交差
AND 既存の公開・鮮度・公式URL条件を通過
```

既存イベントは両項目が未設定でも `/events` への掲載を維持する。これにより766件全体への一括分類を避け、夏ハブ対象だけを明示的にレビューできる。年付きHub IDを抽出キーにするため、将来の `summer-2027` が2026年ページへ混入しない。

### 日程精度のための任意項目

複数の非連続開催日を範囲として扱うと、「今週末」と開催日順が誤るため、次を任意追加する。

```ts
occurrence_dates?: string[]; // YYYY-MM-DD、昇順、重複なし
```

- 非連続開催: `occurrence_dates` を判定と次回日計算に使う
- 毎日開催・連続開催: 既存 `start_date` / `end_date` を使う
- 表示文言は既存 `date_label` を維持する

### 街の祭りを扱うための会場対応

現行は既存施設に紐づく `facility_id` が必須で、街路・河川敷・複数会場の祭りを登録しにくい。架空の施設レコードを作らないため、v1では次を推奨する。

```ts
facility_id: number | null;
venue_name?: string;
```

- 既存施設が真の会場なら従来どおり `facility_id` を使う
- 市街地、河川敷、複数会場なら `facility_id=null` とし `venue_name` を必須にする
- カードは施設名の代わりに `venue_name` を表示し、存在しない施設ページへのリンクを出さない
- 都県は既存 `prefecture` を使い、新しい地域マスタは増やさない
- visibility判定は「有効な既存施設ID」または「`facility_id=null` かつ空でない `venue_name`」のいずれかで通過可能にする
- EventCardは `venue_name` を会場名として表示し、`facility_id=null` では施設リンクを描画しない
- JSON検証は `facility_id=null` の場合に `venue_name` を必須とし、空文字も拒否する
- 汎用 `/events` と都県別一覧でも、既存施設IDがないイベントを同じ公開条件で表示できるようにする
- 上記は確定データ設計へ含めるが、Research後の採用GOまでは型・判定・UIを変更しない
