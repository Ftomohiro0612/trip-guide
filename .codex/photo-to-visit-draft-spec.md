# 写真からおでかけ記録候補をまとめて作る（専用画面・複数写真・必ず確認後保存）

> 作成: 2026-06-14 / 改訂: 2026-06-14（1枚→複数写真バッチへ拡張）/ 改訂: 2026-06-15（new画面トップへ導線追加・候補施設を visibleFacilities 限定）/ Claude Code PM（memorips-claude）
> オーナー方針確定: 専用画面・**複数写真(初期上限10枚)**・GPSで近い施設提案・同一日付＋同一施設はまとめる・**自動保存せず必ず確認画面**・保存する記録だけチェックして一括作成・**候補施設は `visibleFacilities` のみ（`exclude_candidate` は出さない）**・`/mypage/visits/new` 先頭にも導線。
> **これはプラン/仕様。実装はPMレビュー＆オーナーOK後に着手。** 反映後も commit/デプロイはPMレビュー → オーナーGOで別指示。

## 目的

カメラロールから複数写真を選び、各写真の **撮影日** と **撮影場所(GPS)** から「おでかけ記録」の**候補（ドラフト）をまとめて作る**。別日・別場所の写真は別ドラフトに分かれ、同じ日・同じ施設の写真は1ドラフトにまとまる。ユーザーが確認・修正してから、保存する記録だけ一括作成する。

## 確定スコープ（オーナー）

- 専用画面 `/mypage/visits/from-photo` を新設（既存フォームに混ぜない）。
- **導線は2か所**: マイページ（`/mypage`）と、**`/mypage/visits/new` の一番上**に「📷 写真からおでかけ記録を作る」ボタンを置く。
- **複数写真を選択可能**。**初期上限は最大10枚**程度。
- 各写真の EXIF 撮影日・GPS をブラウザ内で一時読み取り。
- 日付＋近い施設候補から記録ドラフトを作成。
- **近隣施設の候補は最大3件**。**1件に確信を持って特定できそうな場合はその1件だけでよい**（無理に3件並べない）。
- **同一日付＋同一施設と推定される写真は同じドラフトにまとめる**。別日・別施設なら複数ドラフトとして並べる。
- **いきなり保存しない**。必ず確認画面でユーザーが日付・施設候補・添付写真を確認/修正してから保存。
- **保存する記録だけチェックして一括作成**。
- **候補に出す施設は `visibleFacilities` のみ**（`data_quality_status === "exclude_candidate"` は GPS最寄り推定・手動検索のどちらでも候補に出さない）。

## プライバシー方針（確定・厳守）

- EXIF の **撮影日時・GPS はブラウザ側で一時的に読み取るだけ**。日付の自動入力と「近い施設の提案・グルーピング」にのみ使用。
- **GPS 生データ（緯度経度）はサーバー送信・DB保存・ログ出力をしない**。提案/グルーピングに使ったら破棄。
- **写真選択時点ではアップロードしない**。保存時に、既存の `VisitPhotoUploader` の EXIF除去・webp再エンコード経路でアップロードする（＝保存画像に EXIF/GPS は残らない）。
- 画面に「位置情報は端末内で候補提案にのみ使い、保存しません」の旨を控えめに明記。

## 既存資産（再利用）

- `app/mypage/visits/VisitPhotoUploader.tsx`: EXIF **撮影日** 読み取り（`normalizeExifDate`/`parseExifDateFromIfd`）＋ canvas で EXIF除去 webp 化＋アップロード。**`MAX_PHOTOS_PER_VISIT = 2`**（1訪問の添付上限＝2枚）。**GPSは現状未パース**（追加実装ポイント）。
- `lib/facilities.ts` の **`visibleFacilities`**（`exclude_candidate` を除外済みの公開対象リスト）: 全施設に `latitude`/`longitude`/`slug`/`name`/`prefecture`/`category`。**GPS最寄り推定の対象母集合はこれを使う**（`facilities`/`data/facilities_data.json` の生配列は使わない）。
- `app/api/facilities/search`（route）: 手動施設検索。既に `exclude_candidate` を除外済み（`isVisibleFacilitySearchSource`）→手動追加でも除外候補は出ない。
- `components/MapView.tsx`: haversine 距離計算。同等ロジックを流用。
- 既存の訪問記録保存処理（`app/mypage/visits/new/page.tsx`）・施設サジェスト（`/api/facilities/search`）。

## 画面・フロー

### 導線
- マイページ（`/mypage`）に「📷 写真からおでかけ記録をまとめて作る」ボタン → `/mypage/visits/from-photo`。
- **`/mypage/visits/new` の一番上（フォームの上）** にも「📷 写真からおでかけ記録を作る」ボタン → `/mypage/visits/from-photo`。手入力フォームより前に置き、写真からの一括作成を先に案内する。new フォーム自体のロジックは変えない（導線ボタンの追加のみ）。

### ステップ
1. **複数写真を選ぶ**（最大10枚。超過分は選択不可＋「最大10枚までです」案内）。この時点ではアップロードしない。
2. クライアント側で各写真について:
   - EXIF **撮影日** を読む（既存ロジック）。取れなければ「日付不明」とし、ドラフト確認画面で「今日」を既定にユーザーが変更可。
   - EXIF **GPS(緯度経度)** を一時的に読む（**新規**: GPS IFD パーサ。読めなければ「位置情報なし」）。
3. **ドラフトへグルーピング**:
   - GPS が読めた写真: **`visibleFacilities`（exclude_candidate 除外済み）** へ haversine 距離を計算し**最寄り施設**を推定（一定距離内、例 ~10km 以内を「その施設付近」とみなす。遠すぎる場合は施設未確定扱い）。
   - グループ化キー = **(撮影日, 推定施設slug)**。同じ日付かつ同じ推定施設の写真 → **同一ドラフト**にまとめる。別日 or 別施設 → 別ドラフト。
   - GPS が読めない/施設遠すぎ: 施設未確定。**同じ撮影日でまとめた仮ドラフト**にし、施設は確認画面でユーザーが手動検索して確定（日付も無ければ要設定）。
   - 各ドラフトには、最寄り施設の**候補を最大3件**（距離付き「約1.2km」・近い順）保持し、確認画面で選び直せるようにする。**1件が突出して近く確信を持って特定できそうな場合（例: 最寄りが十分近く2位と差が大きい）はその1件だけを既定提示にしてよい**（無理に3件並べない）。候補はすべて `visibleFacilities` 内のみ。
4. **確認画面（必須・ここで保存しない）**: ドラフトを一覧表示。各ドラフトに:
   - **訪問日**（編集可。EXIFから自動、無ければ今日）
   - **施設**（最寄り候補 最大3件から選択、または施設名検索で手動選択/変更）
   - **添付写真**（そのドラフトにまとまった写真のサムネイル）
   - **保存するか**のチェックボックス（既定 ON でよい）
   - 添付写真の **上限=2枚（MAX_PHOTOS_PER_VISIT）**。1ドラフトに**3枚以上**まとまった場合は、**ユーザーに添付する2枚を選ばせる**（残りは添付されない＝記録自体は1件のまま）。選ばなければ「添付は2枚まで・残りN枚は添付されません」と案内し、先頭2枚を既定添付にする等の安全な既定にする。
5. **一括作成**: チェックされたドラフトだけを保存。各ドラフトの保存 = 既存の visits 保存処理＋写真アップロード（**保存時に**既存 EXIF除去/webp化経路でアップロード）。
   - 子ども選択・満足度・任意項目: 本画面では最小限（日付・施設・写真）に絞り、保存後に各記録の編集で詳細を足せる方針でよい（実装が重くなりすぎないため）。※ここは実装しやすさ優先で、PMレビュー時に相談可。
6. 保存後は履歴（`/mypage/visits`）へ遷移し、作成された記録が並ぶ。

### GPS パーサ要件（新規・最小）
- JPEG の EXIF GPS IFD から `GPSLatitude`/`GPSLatitudeRef`/`GPSLongitude`/`GPSLongitudeRef` を読み 10進度へ変換。
- 取得緯度経度は **state 内で一時利用のみ**。fetch body / Supabase / ログに出さない。保存・グルーピング完了後に破棄。
- HEIC 等読めない形式・GPSなしは「位置情報なし」で手動施設検索フォールバック。

## エッジケース

- 写真0枚/全部読めない: 案内のみ。
- 10枚超選択: 受け付けず案内。
- 同日・同施設が4枚以上: 1ドラフト＝1記録（訪問は1回）。添付は2枚選択、残りは添付されない旨を明示。
- 同日だが施設バラバラ: 施設ごとに別ドラフト。
- 全ドラフトのチェックを外す: 保存ボタン無効。

## 触らない / 注意

- 既存 `VisitPhotoUploader` の EXIF除去・webp化・アップロード経路・`MAX_PHOTOS_PER_VISIT=2` は壊さない（GPS読みは別関数で追加、保存画像に GPS を残さない）。
- 既存 new/編集フォーム・他ページは、必要最小の連携以外変えない。
- データ系（facilities_data.json）・地図・共有文は触らない。
- `PHOTO_UPLOAD_ENABLED` フラグ配下（既に true）。
