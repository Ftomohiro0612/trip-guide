# MEM-NLSEARCH-001 — 「話して探す／文章で探す」自然文施設検索 (Owner GO: 2026-09-17)

発注元: Memorips PM / 実装: Claude Code (PM) / base: `origin/main` @ `57b5dcda`

## 0. Owner確定方針 (2026-09-17)

> 「話して探す／文章で探す」をGOします。想定体験は「今日雨だから、豊洲の近くで3歳でも遊べて無料の
> ところ」のような自然な発話・文章から、既存のエリア・年齢・雨・無料・カテゴリ等の検索条件を読み取り、
> その条件で検索できることです。まずは既存のMemorip検索軸へ落とす範囲を優先し、新しいLLM基盤・
> vector DB・有料AI依存を先回りで導入しないでください。それらが必要になる場合はOwnerへ戻してください。

**解釈の確定(PM)**: 「話して」と「文章で」は同一機能の2つの入力手段(音声入力 / テキスト入力)であり、
どちらも同じ解析ロジックに流れる1つの検索体験として実装する。音声入力は**ブラウザ標準の
Web Speech API**(`SpeechRecognition` / `webkitSpeechRecognition`)を使う音声→テキストの
ディクテーションのみとし、外部AI APIへ音声や文章を送信しない。テキスト→検索条件の解析は
**決定的なルールベース(辞書引き・正規表現)** で行い、LLM API呼び出し・vector DB・埋め込み検索は
使わない。ネットワーク呼び出しを伴わずクライアント側で完結させる(既存 `/facilities` への遷移を除く)。

## 1. 前提 — 現在の検索軸とデータをそのまま使う(コードで確認済み、base `57b5dcda`)

- 施設一覧のフィルタ軸は `lib/filter.ts` の `FilterParams` が正本: `prefectures`(都道府県id配列)・
  `categories`(カテゴリid配列)・`indoor`(`屋内`/`屋外`/`両方`)・`rain`(`◎`/`△`/`×`)・
  `fee`(`free`/`paid`)・`tags`(`無料`/`完全屋内`/`屋外`/`屋内外両方`/`0-3歳OK`/`小学生向け`/
  `冬季限定`/`季節限定`)・`q`(フリーテキスト、`name`/`address`/`description`/`category`/
  `prefecture`/`target_age`/`tags` の部分一致)。`buildQueryString()` で `/facilities?...` に変換できる。
- 都道府県は `lib/facilities.ts` の `prefectures`(id + 日本語name、47件)、カテゴリは同じく
  `categories`(`data.metadata.categories`)が正本。**辞書はこれらから動的に構築し、ハードコードで
  二重管理しない。**
- 年齢は構造化タグが2種のみ(`components/ChildAgeQuickFilter.tsx` の `ageToTag()` 参照):
  0〜3歳→`0-3歳OK`、6〜12歳→`小学生向け`。4〜5歳に対応するタグは無い
  (**新設しない。この間隙は本トラックの対象外**)。
- 「豊洲」のような市区町村・地名レベルの粒度は `prefectures`(都道府県のみ)にも `tags` にも存在しない。
  現在地からの距離検索(`lib/facility-nearby.ts`)はブラウザGeolocation座標が前提で、地名文字列を
  座標へ変換する仕組みは無い。**新しいジオコーディング基盤は追加しない**。地名トークンが
  都道府県名に一致しなければ、`q`(住所部分一致)に渡して吸収する。
- キーワード検索の入口は現状 `components/HeroSearch.tsx`(施設名/エリア名の短いキーワード用
  オートコンプリート、`/api/facilities/search?q=`)のみで、文単位の自然文は想定していない。

## 2. 実装すること

### 2-1. 自然文パーサー(新規、決定的ロジック)

新規モジュール(例: `lib/natural-language-query.ts` — ファイル名はCodex相当が決めてよい)で、
入力文字列 → `Partial<FilterParams>` 相当を返す。ルールベースの例:

- **雨**: 「雨」「雨天」「梅雨」「屋内」等 → `indoor: ["屋内"]` および/または `rain: ["◎"]`
  (どちらに倒すか一貫させ、報告に明記すること)。
- **無料**: 「無料」「タダ」「お金をかけずに」「0円」等 → `fee: "free"`。
- **年齢**: 「n歳」「n才」「満n歳」等の数値表現、および「未就学」「赤ちゃん」等の定性表現を
  `ageToTag()` 相当のロジック(0〜3→`0-3歳OK`、6〜12→`小学生向け`)へ写像して `tags` に追加。
  対応外の年齢(4〜5歳等)はタグを付けず握りつぶす(誤ったタグを付けない)。
- **都道府県/エリア**: `prefectures`(id・name)と前方一致・部分一致で照合できたトークンは
  `prefectures` へ。一致しない地名トークン(「豊洲」等)は削除せず `q` に残す
  (住所部分一致に使われる)。
- **カテゴリ**: `categories`(id・name)との一致トークンを `categories` へ。
- 上記いずれにも当てはまらない残りの語(助詞・接続語を除いた実質的なキーワード)は `q` に連結する。
- パース結果は失敗してもエラーを投げず、**空のFilterParamsに近い状態にフォールバックしてよいが、
  `q` にはユーザーの原文(または残差)を必ず残す**(何も引っかからなくても検索自体は実行できること)。

### 2-2. 入力UI(新規)

- 既存の `HeroSearch`(短いキーワード用)は維持しつつ、**トップページのHero内**に、文単位の
  自然文を入力できる新しい入口を追加する(例: 「文章で探す」の切替タブ/展開ボックス。
  具体的な見た目・配置はCodex相当が決めてよいが、既存の検索訴求を隠さないこと)。
- テキスト入力に加えて、**対応ブラウザでのみ**マイクボタンを表示し、`SpeechRecognition`
  (`lang: "ja-JP"`)でディクテーションしテキスト欄に反映する。`window.SpeechRecognition` も
  `window.webkitSpeechRecognition` も存在しない場合はマイクボタン自体を出さず、テキスト入力のみ
  機能させる(壊れたボタンを出さない)。
- 送信時: 2-1のパーサーでテキストを解析 → `buildQueryString()`(`lib/filter.ts`)で
  クエリ文字列化 → `/facilities?...` へ遷移する。
- 解析結果の可視化は新規に作らず、**既存の `components/ActiveFilterChips.tsx` をそのまま使う**
  (`/facilities` 側で読み取られた条件がチップとして出る。ユーザーが誤解釈に気づいて外せる)。

## 3. 受入条件 (AC)

- **AC-1**: トップページのHero内に、文章(複数語からなる自然文)を入力できる検索入口があり、
  既存の `HeroSearch`(短いキーワード検索)は回帰なく残っている。
- **AC-2**: Web Speech API対応ブラウザ(Chromium系)でマイクボタンが表示され、音声入力した内容が
  テキスト欄に反映される。**未対応ブラウザではマイクボタンが表示されない**(Playwright上で
  `SpeechRecognition` 未定義の環境をエミュレートして確認)。
- **AC-3 (中心シナリオ)**: 例文「今日雨だから、豊洲の近くで3歳でも遊べて無料のところ」を入力・送信すると
  `/facilities` へ遷移し、以下が同時に成立する:
  - `fee=free` が適用されている(または同義のUI状態)
  - `0-3歳OK` に対応する年齢タグが適用されている
  - 雨条件(`indoor=屋内` または `rain=◎`、2-1で確定した方)が適用されている
  - `q` に「豊洲」相当の残差が含まれており、東京都の施設のうち住所に「豊洲」を含むものが
    存在すれば結果に現れる(存在しなくても検索自体はエラーなく完了する)
  - `ActiveFilterChips` に適用された条件が表示される
- **AC-4**: 都道府県名を含む例文(例:「静岡県で無料の屋内施設」)で `prefectures` が正しく
  絞り込まれる。
- **AC-5**: 解析に失敗する・条件が1つも取れない自然文を入力しても、画面が無言で固まらず、
  `q` に原文を積んだ通常検索として `/facilities` へ遷移する。
- **AC-6 (依存の非追加)**: 本トラックの実装に、新しい外部LLM API呼び出し・vector DB・有料AI
  サービスへの依存が追加されていないこと(コード上、パース処理がネットワーク呼び出しを行わないこと。
  音声認識はブラウザ標準APIのみ使用していること)。
- **AC-7 (回帰)**: `/facilities` の既存フィルタUI(`FilterSidebar`/`MobileFilterBar`/
  `ChildAgeQuickFilter`/`PrefectureSelector`/`SortSelect`)およびイベント検索
  (`app/events/**`)に変更・回帰が無いこと。
- **AC-8**: `npm run lint` と `npm run build` が exit 0。

## 4. 非ゴール / HOLD

- 汎用的な自然言語理解(任意の言い回しを高精度で解釈するNLP)は目指さない。既存の検索軸へ
  写像できる範囲が対象。
- イベント検索(`/events`)への自然文検索の適用。本トラックは施設検索(`/facilities`)のみ。
- 市区町村・地名レベルの新しい地理データモデル/ジオコーディング基盤の新設。
- 4〜5歳向けの新しい年齢タグの新設。
- 新しいLLM基盤・vector DB・有料AI依存の導入(Owner明示禁止)。**必要になった場合は実装を止めて
  PM経由でOwnerへ戻すこと。**
