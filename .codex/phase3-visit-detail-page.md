# Phase 3: 訪問記録詳細ページ

> 作成: 2026-06-11 / Claude Code PM
> 前提: MEMORIPS_AI_ROLES.md / product-direction.md / HANDOFF.md を読むこと

---

## 目的

メモリップは施設レビューサイトではなく**家族ごとのおでかけ記録サービス**。
1回のおでかけ（visit）について、施設・日付・参加した子ども・子どもごとの反応タグ・満足度・また行きたい・親のメモを見返せる詳細ページを作る。

---

## 着手前の必須調査

実装前に既存コードを必ず確認すること:

1. Phase 2 で実装済みの訪問記録一覧・記録フォームのファイル構成（`app/` 配下の visits 関連ルート、components）
2. Supabase スキーマ: `visits` / `visit_children` / `visit_child_tags` / `reaction_tags` / `children` テーブルの実際のカラム名・リレーション
3. 既存の Supabase クライアント取得パターン（server / client どちらで認証セッションを取るか）
4. 既存の編集・削除導線（あるならその UI/ルーティング規約に合わせる）

---

## 要件

### ルーティング

- 既存の一覧からの遷移規約に合わせる（例: `/visits/[id]`。既存に規約があればそちら優先）。

### 認可（最重要）

- **RLS を前提としつつ、アプリ層でも所有者チェック**を行う:
  - サーバー側でセッションユーザーを取得し、visit の `user_id` と一致しない場合は 404（403ではなく404にして存在を漏らさない）。
  - 未ログインはログインページへリダイレクト（既存パターンに従う）。
- クエリは必ずセッション付きクライアントで実行（service role キーは使わない）。

### 表示内容

- 施設情報: 施設名（`facility_id` が紐づく場合は施設詳細ページ `/facilities/[slug]` へのリンク）。施設が削除済み・未紐付けの場合は施設名テキストのみか「施設情報なし」。
- 日付（訪問日）
- 参加した子ども（複数可）: 子どもごとにカードで
  - 名前・（あれば）年齢
  - 反応タグ（reaction_tags のラベル・絵文字チップ）
  - 満足度（★表示）
  - また行きたい（あれば表示）
- 親のメモ（自由テキスト。改行を維持して表示）

### UI

- スマホ優先のカード UI。既存の Tailwind トーン（rounded-2xl/3xl, slate, sky/cyan/emerald）に合わせる。
- 子どもごとのセクションは将来の写真表示を想定し、カード内に拡張しやすい構造にする（例: 子カードをコンポーネント化）。

### 編集・削除導線

- 既存仕様と整合させる。既存に編集フォーム・削除処理があるならリンク/ボタンを設置。なければ「編集」「削除」ボタンの placeholder は置かず、今回は表示のみとする（勝手に新規実装しない。既存があるかをまず確認）。

### プライバシー

- このページは**本人専用ページ**。metadata は `robots: { index: false }` を設定。
- 子ども名・メモなどの個人データを公開ページ（施設ページ等）に出さないこと。OGP も生成しない。
