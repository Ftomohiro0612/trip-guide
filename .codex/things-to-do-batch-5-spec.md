## 機械チェック（全件・提出前に自己実行）

- 文字種・動詞止め・項目数3〜12・項目内重複なし
- 1項目は**35文字以内**（上限のみ。下限はなし — 自然な項目は9〜15字が標準。「長すぎないこと」のガードであり、字数合わせの修飾語追加は禁止）
- 禁止語: 出典不明評価 / 公式根拠なしの持込可否・ベビーカー・駐車場・授乳室・おむつ替え・食事・営業時間・料金詳細
- **語尾分布**: 同一語尾が全体の50%超なら NG
- **高頻度修飾語チェック（batch-4 教訓）**: 「じっくり」「親子一緒に」「細かな」「迫力ある」等の詰め物修飾語が同一語で全体の5%超なら NG
- **高頻度フレーズチェック（batch-5 追加・オーナー指示）**: 語尾だけでなく、文中に繰り返される2〜4語の定型フレーズ（例「〜を見て回る」「〜を体験する」の機械的連発）を検出。上位フレーズと件数を報告に含める
- 単語重複バグ（「じっくりじっくり」等）なし
- NHR 24件リスト + exclude_candidate 4件 照合結果を報告に含める

## 東京特有の注意（オーナー指示・batch-4 から継続）

1. **屋内遊び場の「雨の日に屋内で遊ぶ」定型文の連発禁止** — rain◎×屋内の条件充足施設のみ、かつ言い回しを固有要素（遊具名・エリア名）に寄せる
2. **商業施設内キッズスペースの差別化** — 同型施設（キドキド系・モーリーファンタジー系・namco系等）は施設固有の遊具・特徴で差別化。**固有要素で差別化できない場合はスキップ**（無理に付与しない）
3. **「写真を撮る」の乱用禁止** — 写真目的が自然な施設のみ
4. **フードコート・飲食・買い物など遊びでない要素を混入させない**
5. **駐車場・ベビーカー・授乳室・おむつ替え等の公式確認必要情報は書かない**
6. **小規模施設に「半日」「1日」表現を使わない**
7. **キャラクターショー・イベント・体験プログラムは開催日注記**（「開催日は公式サイトで確認」等）を漏らさない
8. **水遊び / プールを厳密に分ける** — pool タグなしに「プールで泳ぐ」を書かない。water_play と pool を混同しない
9. **同一ブランド・同カテゴリ間の類似チェック** — 同一ブランド・同カテゴリ施設で things_to_do が**3項目以上同一またはほぼ同義**になっていないか機械チェック。キドキド系・モーリーファンタジー系・namco系・屋内プレイランド系・科学館/博物館系は特に確認。差別化できない場合はスキップしてよい。施設固有の遊具名・展示名・体験名がある場合のみそれを優先して反映。**報告にブランド/カテゴリ別の類似チェック結果を含めること**

## 反映フェーズ（PM GO 後・別メッセージで指示）

PMのGO後、以下を実行（**デプロイはしない**）:
1. 承認分を facilities_data.json に反映（things_to_do のみ）
2. audit で意図しないカテゴリ変動がないこと確認
3. push-to-sheet → sync 往復で diff ゼロ
4. `npm run build`（prerender 検証）
5. lint / build PASS 確認
6. 変更施設数 = 承認件数 一致（差分サマリ）、things_to_do 以外に差分なし
7. **代表施設の PC/SP スクショ**で 2カラム崩れ・長文折返し・余白過多がないこと確認
8. 検証結果を agmsg で報告 → **デプロイ可否は PM/オーナーが別途判断**
