# url未入力102件 公式URL調査 方針

> 作成: 2026-06-12 / Claude Code PM（オーナー指示の転記+運用設計）
> 目的: 体験候補の小ロット展開前に、根拠が弱い施設（url未入力102件）の一次情報URLと data_quality_status を整える

## 役割分担

- **調査**: Claude Code PM 側（WebSearch エージェントに厳格ルールを課して実施。Codex は Web 検索不可のため）
- **JSON反映**: Codex（PM が確定した調査結果一覧をもとに source_urls / source_checked_at / data_quality_status / url を更新）
- **最終判断**: 怪しいものは PM レビュー → 必要に応じオーナー確認

## URL優先順位

1. 公式サイト
2. 自治体・公的施設ページ
3. 運営会社ページ
4. 施設が属する大型施設・公園・複合施設の公式ページ
5. 信頼できる観光協会ページ

まとめサイト・口コミサイト・個人ブログ・Google検索結果URLでは confirmed にしない。

## status 判定基準

| 状態 | 条件 |
|---|---|
| confirmed | 公式/自治体/運営元URLで名称・住所・施設内容まで明確に一致確認（facility-provenance-schema.md の4条件充足） |
| likely_ok | 一次情報URLが見つかり概ね一致するが、住所等の完全一致確認まではしていない |
| needs_web_check | URLは見つかったが名称・住所・営業状態に不安がある |
| needs_human_review | 閉店・移転・名称変更・同名施設混同の可能性 |
| exclude_candidate | 県外・閉業・対象外の可能性が高い（**削除はPM確認後**） |

## 記録ルール

- 見つけたURL → `source_urls`（先頭=最重要ソース）。ユーザー向け `url` にも同じ公式URLを設定（公式サイト/施設ページの場合のみ。自治体の施設一覧ページ等しかない場合は url 設定は個別判断）
- 確認日 → `source_checked_at`（YYYY-MM-DD）
- 状態 → `data_quality_status`
- **住所・料金・営業時間・対象年齢はこのタスクでは変更しない**（閉店・住所相違を発見したら status と調査メモに記録し、修正は別タスク）

## 進め方（オーナー確定）

1. **サンプル10件**: 多様なタイプ（チェーン店内施設 / 公営公園 / 市民プール / モール内キッズスペース / スキー場 / 大手テーマパーク隣接 / 公園内動物広場 / 住所不詳 / 観光施設 / 小規模工房）で調査 → 結果をオーナー確認 → コミット1
2. **全102件**: サンプルで方針確定後に実施。一括自動確定はせず、status 別サマリと判断例をレビューしてから Codex に反映指示 → コミット2
3. 反映後: audit スクリプト実行（url_na_or_empty 件数の減少確認）+ push-to-sheet で Sheets 整合
