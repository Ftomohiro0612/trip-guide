## 対象規模の見込み

- 全1,030件 − パイロット5件 − needs_human_review 24件 − needs_web_check 1件 − url未入力25件 − 根拠不足スキップ分
- 概算 **900〜950件 ≒ 最大19バッチ**。ただし第1期は「confirmed/likely_ok/url有り」の優先対象から開始し、全件完走を急がない（残りは url調査・修正タスクの進捗に合わせて追加）

## 各バッチの標準サイクル（1バッチの目安: 生成〜反映で半日）

1. Codex: 抽出リスト提出（10分）
2. Codex: 生成 + 機械チェック → batch-N.json（〜1時間）
3. PM: チェックリストレビュー → 修正ループ（〜1時間）
4. オーナー: 確認（フェーズに応じ全件 or 境界例）
5. Codex: 承認分反映 → audit → 往復 → build → commit（30分）
6. 複数バッチごとにデプロイ

## デプロイとモニタリング

- デプロイ単位: 2〜3バッチごと（毎バッチはしない）
- デプロイ後確認: 反映施設のサンプル3件 + 未適用施設1件（フォールバック）+ 主要導線
- 公開後に表現の問題が見つかった場合: 該当施設の things_to_do を修正 or フィールド削除（個別対応）

## ロールバック手順

1. **個別施設**: things_to_do フィールドを削除 → フォールバック表示に自動復帰 → commit → デプロイ
2. **バッチ単位**: `git revert <batchコミット>` → build → デプロイ
3. **全面**: `node scripts/remove-things-to-do.mjs`（フェーズ0で用意。パイロット5件を除く全 things_to_do を除去）→ build → デプロイ
4. いずれも Sheets は `push-to-sheet` で再同期

## 中断条件

- バッチレビューで重大指摘（事実誤り・禁止表現）が**1バッチに3件以上** → 生成ルールを見直すまで次バッチに進まない
- 本番で施設からの指摘・問い合わせが発生 → 該当施設を即時修正し、同型の問題を全反映分で横断チェック
